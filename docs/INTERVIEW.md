# 面试版使用说明（v1.1.0）

> 这份文档只服务一个目标：让你在 30 秒内说清项目、在 3 分钟内演示完、在 10 个追问里不翻车。
> 面试版请保持稳定，不再往 main 上加功能；v2 的产品化能力在独立分支演进。

## 1. 一句话与两分钟介绍

**30 秒版**

> 我做了一个考研数学刷题平台，Spring Boot 3 + MyBatis + MySQL + Vue 3，覆盖题库、练习、日报/掌握度、艾宾浩斯复习四个模块。项目有 25 个测试、三容器 Docker 部署。我比较得意的点是：做题计时全部在服务端算；掌握度和复习调度抽成无框架依赖的纯函数；日报用一次批量查询替代了原来的 N+1。

**两分钟版（按“问题 → 方案 → 结果”讲）**

1. **问题**：考研数学刷题工具很多，但“刷完不知道哪里弱、错题没人讲、复习没节奏”是常见断点。
2. **方案**：题库支持 Excel 幂等导入；练习由服务端计时判分；日报按知识点算掌握度；答错自动进艾宾浩斯队列。
3. **结果**：25 个测试全绿，三容器可一键起；本机压测知识点树 1579 QPS、日报快照 1317 QPS；报告查询从 4N+1 次降到固定 6 次。

## 2. 架构

```text
浏览器
  │
  ▼
Nginx（Vue 3 静态资源 + /api 反向代理）
  │
  ▼
Spring MVC（Controller / Service / MyBatis）
  │                 │
  ▼                 ▼
MySQL 8          领域纯函数
（7 张表）        MasteryCalculator / EbbinghausScheduler
```

- 后端分层：`controller → service → mapper`，统一 `Result`、全局异常、参数校验。
- 领域算法不依赖 Spring，单测毫秒级。
- 前端 `api/normalize.js` 统一适配后端 VO 与 mock 字段。
- 部署：`docker compose` 三服务（MySQL / 后端 / Nginx），后端 healthcheck 通过后前端才启动。

## 3. 三分钟演示脚本

**0:00–0:30 启动**

```bash
cd kaoyan-math-platform
MYSQL_PORT=3307 docker compose up -d --build
docker compose ps
```

预期：`kaoyan-mysql (healthy)`、`kaoyan-backend (healthy)`、`kaoyan-frontend (up)`。
打开 `http://localhost:5173`。

**0:30–1:10 题库**

- 展示题库列表：题型/难度/知识点标签、公式渲染。
- 上传 Excel，展示 `3 行 → 2 入库 + 1 重复`；再传一次，`0 入库 + 3 重复`。
- 点一句：“去重靠 `content_hash` 唯一键 + 文件内 `seenHashes` 双层。”

**1:10–1:50 练习**

- 随机抽 3 题，演示单选/填空。
- 故意答错一题，展示“服务端计时 2 秒”和正确答案/解析。
- 演示大题：先提交占位答案，看到答案后点“我答错了/我答对了”（两步自评）。

**1:50–2:30 报告**

- 打开日报：题数、正确率、平均用时、知识点掌握度/薄弱点。
- 说明：“今天实时算，历史日期才落快照；区间查询逐日补 0，趋势图不断点。”
- 点一句优化：“报告原来每道题 4 次查询，50 题约 200 次；现在批量查，固定 6 次。”

**2:30–3:00 复习与收尾**

- 复习页展示到期任务；点“记住了”推进到下一轮，或“忘了”重置。
- 打开 Swagger，说明统一响应/异常状态码。
- 收尾：“单用户是 v1 的主动取舍，`user_id` 和按用户查询都已预留，v2 做认证时不重写。”

## 4. 十个高频追问

1. **为什么用 MyBatis 不用 JPA？**
   SQL 可控，索引、聚合、分页都能在明面上优化；这个项目的主要学习素材就是 SQL。代价是模板代码多，所以用 Mapper XML + 统一 resultMap 控制。

2. **为什么是单用户？**
   v1 不为假想中的账号体系写代码；`user_id` 字段、日报/复习唯一键、按用户查询都预留了。多用户是产品阶段的事，不是面试版的缺陷。

3. **做题时长怎么防前端造假？**
   `started_at` 由服务端在开始练习时写入，提交时 `now - started_at`，前端传什么都不参与计算；重复提交由 `submitted_at IS NULL` 条件更新兜底。

4. **`content_hash` 为什么用 SHA-256？**
   导入幂等只需要“内容指纹”，但 MD5 抗碰撞弱；改成 SHA-256 后列宽 32→64，重复导入仍验证为 0 入库 / 3 重复。

5. **日报为什么要“今天实时、历史快照”？**
   最初所有日期首次查看就固化，结果当天新做题后日报还是旧数字；现在今天实时算，历史日期才落快照，区间查询补 0，兼顾一致性和趋势图。

6. **N+1 是怎么发现、怎么修的？**
   报告每道题会查题目、最近 5 次作答、知识点关联、知识点名，50 题约 200 次查询。改成 `selectByIds` + `ROW_NUMBER()` 窗口函数批量取最近 N 次 + 批量知识点查询，固定 6 次。

7. **并发重复提交/重复入队怎么防？**
   提交用 `UPDATE ... WHERE submitted_at IS NULL` 并检查影响行数；复习入队用 `active_key` 生成列 + 唯一索引 + `ON DUPLICATE KEY UPDATE`；复习推进也带 `status=0` 条件。

8. **异常为什么改 HTTP 状态码？**
   原来所有错误都返回 HTTP 200 + body code，监控和前端都没法区分。现在参数错误 400、资源不存在 404、唯一键冲突 409、系统错误 500，前端统一错误拦截。

9. **为什么把掌握度/复习调度抽成纯函数？**
   它们是领域规则，不依赖 Spring；固定 `Clock` 后单测毫秒级，艾宾浩斯周期不用改系统时间。也强制了“领域与框架分离”。

10. **Docker 里踩过什么坑？**
    - 本机 3306 被占用 → `MYSQL_PORT=3307`；
    - BuildKit 构建容器不继承宿主代理 → compose build args + `MAVEN_OPTS`；
    - MySQL 初始化中文乱码 → schema 首部 `SET NAMES utf8mb4`；
    - 后端 healthcheck 通过后前端才启动，避免 Nginx 先起来打不到后端。

## 6. 踩坑故事（比“一切顺利”更加分）

1. **单测全绿但应用起不来**：mapper XML 注释里写了 `-----` 分隔线，XML 注释不允许 `--`，MyBatis 启动解析失败。后来补了 `MapperXmlWellFormedTest`，用标准 XML 解析器守门。
2. **大题提交 NPE**：`Boolean` 三元表达式和 `boolean` 混用，`selfEval=null` 时拆箱空指针；拆成显式分支，并补了两步自评接口。
3. **前端 mock 和真实后端两套字段**：mock 用 `records/type:'SINGLE'`，后端用 `list/type:1`；页面在 mock 下正常、真实模式空白。后来加 `api/normalize.js` 适配层 + `check:contract` 脚本，并用 headless 浏览器渲染四个路由验证。
4. **报告快照过期**：当天第一次看报告后，新做题不更新；改成“今天实时、历史快照”。
5. **Docker 构建卡住**：daemon 能拉镜像，但 BuildKit 的 `RUN mvn` 没有代理；用 compose build args 注入 `HTTP_PROXY/HTTPS_PROXY/MAVEN_OPTS`。

## 8. 边界与不要主动说

- 不主动说“单用户所以不能上线”；被问到时说“v1 主动砍掉账号体系，`user_id` 和按用户查询已预留，产品阶段做认证”。
- 不主动说“AI 讲解”是 v1 的能力；v1 只有解析文本，AI 是 v2。
- 不把 QPS 说成生产容量；说明是本机单实例基线。
- 不承诺“高并发/高可用”；说清楚当前是单机 Docker Compose，下一步才是 Redis、监控、多实例。
