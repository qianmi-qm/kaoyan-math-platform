# v2 说明：Redis 报告缓存 + AI 错题讲解

> 分支：`v2`；基线：`v1.1.0-interview`（面试稳定版）
> 范围：只做增量，不动 v1 的表结构和四大模块核心逻辑；仍是单用户。

## 1. 这一版做了什么

| 编号 | 功能 | 实现 |
|------|------|------|
| F2 | 报告缓存 | Redis Cache-Aside：`report:{userId}:{date}`，TTL 25 小时 + 随机抖动；练习提交/自评后先更 DB 再删缓存 |
| F1 | 错题 AI 讲解 | `POST /api/ai/explain/{recordId}`，SSE 流式返回；成功后落 `ai_explanation`，二次查看不再调模型 |
| 降级 | Redis / LLM 不可用 | Redis 连接失败 30 秒熔断、降级查库；后端不硬依赖 Redis healthy，Redis 挂了也能启动；无 key/超时/报错时返回参考解析，页面不 500 |
| 数据 | AI 需要的上下文 | `practice_record.submitted_answer` 保存用户答案；`ai_explanation` 存讲解全文 |
| 部署 | 四容器 | MySQL + Redis + 后端 + Nginx 前端；后端等 MySQL/Redis healthy 才启动 |

## 2. 架构

```text
浏览器
  │  /api/ai/explain/{recordId}  (POST, SSE)
  ▼
Nginx（proxy_buffering off）
  │
  ▼
Spring MVC
  ├── ReportService ──► Redis（Cache-Aside）──► MySQL（快照/实时聚合）
  └── AiExplanationService ──► OpenAI 兼容 /chat/completions（SSE）
                              └── ai_explanation（成功后落库，二次复用）
```

## 3. 报告缓存设计

- key：`report:{userId}:{date}`；value：`DailyReportVO` JSON。
- 读：Redis 命中直接返回；未命中查库/生成，回填 Redis。
- 写：练习提交、大题自评后 **先更新 MySQL，再 `DEL` 缓存**。
- TTL：`90000s + 随机 0~600s`，防止同一批 key 同时过期。
- 故障：Redis 异常后 30 秒内直接跳过缓存，避免每个请求等连接超时；页面仍返回 DB 数据。后端不依赖 `redis healthy`，Redis 挂掉时服务仍可启动（缓存自动降级）。
- 语义配合 v1：今天实时计算，历史日期落 `daily_report` 快照后再缓存。

## 4. AI 讲解设计

- 接口：`POST /api/ai/explain/{recordId}`，`text/event-stream`。
- 上下文：题目、选项、用户答案、正确答案、参考解析、知识点。
- Prompt：要求“用户为什么错 / 正确思路 / 易错点”，明确“不要编造教材原文”。
- 流式：WebClient 订阅 OpenAI 兼容 SSE，逐段 `SseEmitter.send`；收到 `[DONE]` 主动收尾（有的实现不立刻断连接）。
- 复用：成功后 `ai_explanation` 按 `(user_id, question_id, answer_hash)` 唯一落库；二次查看直接流式返回 DB 文本，不同错答分别生成。
- 降级：无 `AI_API_KEY`、超时、HTTP 错误、空返回时，退化为参考解析 + 正确答案，仍以 SSE 返回并正常结束。
- 成本：落库复用 + 上下文截断（默认 4000 字符）；v3 再上 RAG 降幻觉。

## 5. 联调证据（2026-10-18）

- 单测：`mvn test` → 25/25 通过（新增功能未破坏 v1 测试）。
- Redis：`GET /api/reports/daily` 后 `KEYS report:*` 出现 `report:1:2026-10-18`；`TTL` ≈ 90159s。
- 失效：提交练习后 key 被删除；再次查询日报 `totalCount` 从 0 变 1，并重新生成 key。
- Redis 宕机：`docker stop kaoyan-redis` 后日报仍 HTTP 200；第一次约 4.5s（连接超时），熔断后第二次 21ms；Redis 恢复后自动回填。
- AI 首调：用本地 mock OpenAI SSE 服务验证，流式返回 `MOCK-AI-...`，收到 `event:done`，`ai_explanation` 落库（`mock-model`）。
- AI 二次：同一记录再次请求，mock 请求计数不增加，直接读库。
- AI 不同错答：同一道题分别提交 A、C 两个错误答案，生成两条 `ai_explanation`，`answer_hash` 不同；各自二次请求都命中自己的讲解，mock 计数不增加。
- Redis 启动降级：停掉 Redis 后 `--no-deps --force-recreate backend`，后端仍 healthy，日报 HTTP 200（首次约 4.5s，熔断后 21ms）。
- AI 降级：无 key 时返回参考解析文本 + `[DONE]`，HTTP 200。
- Nginx：`POST http://127.0.0.1:5173/api/ai/explain/{id}` 能正常逐段返回，代理未缓冲。
- 四容器：`kaoyan-mysql healthy`、`kaoyan-redis healthy`、`kaoyan-backend healthy`、`kaoyan-frontend up`。

> 说明：本机没有真实 LLM key，AI 流式链路使用本地 mock OpenAI 兼容服务验证；换成真实 key 只需改 `.env` 的 `AI_BASE_URL / AI_API_KEY / AI_MODEL`。

## 6. 配置

```bash
cp .env.example .env
# 必改：MYSQL_ROOT_PASSWORD
# 可选：AI_API_KEY=sk-...；不填则 AI 自动降级为解析
MYSQL_PORT=3307   # 本机 3306 被占用时
docker compose up -d --build
```

- `AI_ENABLED`：总开关。
- `AI_BASE_URL`：OpenAI 兼容 base url，默认 `https://api.deepseek.com/v1`。
- `AI_MODEL`：默认 `deepseek-chat`。
- `REDIS_HOST / REDIS_PORT`：本地默认 `localhost:6379`；Docker 内为 `redis:6379`。

## 7. 边界与后续

- 仍是单用户：`CurrentUser` 固定 `user_id=1`，没有登录/配额/计费；这是产品阶段的事。
- F3 打卡排行榜按 v2 文档顺延，未实现。
- 没有对 LLM 输出做内容审核/敏感词过滤；上线前要补。
- 没有对 AI 调用做用户级限流和成本核算；产品阶段必须补。
- 真实 provider 的 SSE 格式可能与 mock 略有差异；已按 OpenAI 兼容格式解析，换 provider 需要回归一次。

## 8. v2 演示脚本（1 分钟）

1. 练习页答错一题，点“AI 讲解”，展示逐字返回。
2. 再点一次同一题，说明“直接读库、不重复消耗 token”。
3. 打开日报，`docker exec kaoyan-redis redis-cli KEYS 'report:*'` 展示缓存 key。
4. 再提交一题，展示 key 被删除、日报数字更新。
5. 可选：`docker stop kaoyan-redis`，刷新日报仍正常，说明降级。
