# v2 包装：面试 / 产品两用

> v2 = v1 业务闭环 + Redis 报告缓存 + AI 错题 SSE 讲解。
> 面试时讲“缓存一致性 + 流式降级”；产品视角讲“AI 是付费点，成本靠落库复用控住”。

## 1. 30 秒版本

> 在 v1 的四模块之上，我给报告加了 Redis Cache-Aside，练习提交后先更 DB 再删缓存；错题讲解走 OpenAI 兼容的 SSE 流式接口，生成成功按“用户+题目”落库，二次查看不重复消耗 token。没有 key 或模型超时会自动降级为参考解析，页面不 500。Docker Compose 现在是 MySQL + Redis + 后端 + 前端四容器。

## 2. 简历 bullet（v2 增量）

- 为日报接口引入 Redis Cache-Aside（`report:{userId}:{date}`，25h TTL + 随机抖动），练习提交后先更新 DB 再删除缓存，读接口 RT 明显下降，并实现 Redis 故障 30 秒熔断降级。
- 基于 OpenAI 兼容接口 + SSE 实现错题 AI 讲解，WebClient 流式转发、逐字输出；讲解按 `(user_id, question_id)` 落库复用，二次查看不再调用模型。
- 设计无 key / 超时 / 模型报错三级降级为参考解析，SSE 正常收尾，页面不 500；Nginx 关闭 `proxy_buffering` 保证流式不被缓冲。
- 扩展 `practice_record.submitted_answer` 与 `ai_explanation` 表，补 Docker Redis 服务与后端 healthcheck，保持 v1 的 25 个测试全绿。

## 3. 一分钟演示

1. 练习页答错一题，点“AI 讲解”，展示逐字出现。
2. 再点一次同题：说明“直接读库，不再调模型”。
3. 打开日报，执行 `docker exec kaoyan-redis redis-cli KEYS 'report:*'`，展示缓存 key 与 TTL。
4. 再提交一题，展示 key 被删除、日报数字更新。
5. 可选：`docker stop kaoyan-redis`，刷新日报仍正常，说明降级。

## 4. 五个追问

1. **为什么先更新 DB 再删缓存？**
   Cache-Aside 的常用顺序。先删缓存再更 DB，读请求可能在两步之间把旧值回填；先更 DB 再删，最坏只是短时间读到旧值，下一次读会回填新值。极端一致性可加延迟双删/订阅 binlog，本项目按业务接受最终一致。

2. **缓存穿透/击穿/雪崩怎么防？**
   穿透：空结果也可短 TTL 缓存（当前日报总会生成 0 值对象，天然不会一直穿透）；击穿：热点 key 过期用互斥/逻辑过期（当前单用户量小，先保留扩展点）；雪崩：TTL 加随机抖动，故障时熔断降级。

3. **为什么用 SSE 不用 WebSocket？**
   AI 讲解是服务端单向推送，SSE 基于 HTTP、无需额外协议升级、断线重连简单；WebSocket 适合双向实时协作，这里不需要。

4. **AI 讲解怎么控成本？**
   成功落库按“用户+题目”复用；prompt 截断到 4000 字符；无 key 不调用；后续可加用户级配额、简单题走小模型、结果缓存。

5. **AI 讲错了怎么办？**
   当前 prompt 明确“不要编造教材原文”，但 v2 仍可能幻觉；v3 计划 RAG 挂知识点原文 + 引用溯源，检索不到就降级声明。产品上线前还要加内容审核与用户反馈入口。

## 5. 产品视角

- **可收费点**：AI 讲解次数/订阅、个性化复习计划、薄弱点诊断报告；免费版保留题库和基础练习。
- **成本项**：token、Redis/MySQL、内容版权、审核；其中 token 靠落库复用 + 配额控制。
- **下一步（产品阶段）**：认证/多用户、支付与配额、RAG 降幻觉、内容审核、运营后台、监控告警。
- **当前边界**：仍单用户、无鉴权/配额/支付；F3 排行榜按文档顺延；真实 LLM 只验证了 mock，换 provider 要回归 SSE 格式。

## 6. 面试时不要主动说

- 不要说“AI 已经商用”；说“技术链路已通，mock 验证，真实 provider 需要 key 回归”。
- 不要把 Redis QPS 说成生产容量；说本机单实例基线。
- 不要回避单用户：说“v2 先验证缓存/AI 技术链路，认证和支付是产品阶段，`user_id` 已预留”。
