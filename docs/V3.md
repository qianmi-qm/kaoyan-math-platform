# v3：JWT 认证与多用户隔离

> 分支：`v3`；基线：`v2.0.3`（单用户 Redis + AI）
> 目标：把固定 `user_id=1` 换掉，让每个用户只看到自己的练习、报告、复习和 AI 讲解。

## 1. 做了什么

| 模块 | 实现 |
|------|------|
| 注册 | `POST /api/auth/register`，BCrypt 存密码，用户名唯一 |
| 登录 | `POST /api/auth/login`，成功返回 JWT（默认 24h） |
| 当前用户 | `GET /api/auth/me` |
| 鉴权 | Spring Security 6 + `OncePerRequestFilter`；除登录/注册/Swagger 外全部要求 Bearer token |
| 角色 | `user.role`（USER/ADMIN）；题库/知识点写接口仅 ADMIN |
| 用户上下文 | `CurrentUser` 从 `SecurityContext` 取 `LoginUser`，删除 `app.default-user-id` |
| 数据隔离 | 所有业务查询继续使用 `user_id` 参数，只是来源从固定值改成登录用户 |
| 前端 | `/login` 登录/注册页；axios 自动带 token；401 清理登录态跳登录；路由守卫；非管理员隐藏题库导入 |
| 迁移 | `AuthSchemaMigration` 给旧 `user` 表补 `password_hash` / `role`；`DemoUserInitializer` 管理显式 demo 账号；`AdminUserInitializer` 独立创建/提升管理员 |

## 2. 关键设计

- **无状态 Session**：JWT 放 `Authorization: Bearer ...`，服务端不存 session，扩容不需要粘性会话。
- **密钥**：`JWT_SECRET` 无默认值，缺失/示例值/少于 32 字节直接启动失败；不再有可伪造的默认 secret。
- **密码**：BCrypt，不存明文；登录失败统一“用户名或密码错误”，不暴露用户是否存在。
- **401 结构**：Security 的 EntryPoint 也返回 `Result{code:4010,...}`，和业务异常一致。
- **SSE 异步**：`SseEmitter` 完成时会走 ASYNC dispatch，Security 放行 `DispatcherType.ASYNC/ERROR`；用户 id 在请求线程取出后传入 `ai-explain` 线程池，不依赖自动跨线程传播。
- **演示账号**：默认关闭；开启时必须显式设置非默认 `DEMO_USER_PASSWORD`，learner 会被提升为 ADMIN。关闭时清空 learner 的历史密码，避免“关了开关仍能登录”。
- **管理员引导**：生产设置 `ADMIN_USERNAME / ADMIN_PASSWORD` 独立创建或提升 ADMIN；`ADMIN_REQUIRED=true` 时缺失密码启动失败。这样关掉 demo 不会导致没人能管题库。
- **权限**：注册用户默认 USER；题库/知识点写接口和题目详情 `hasRole('ADMIN')`，普通用户只读；题目/知识点仍是共享资源。
- **限流**：登录按 `username+IP` 5 次/5 分钟 + IP 30 次/5 分钟；注册按 IP 10 次/小时；超限 429。当前单实例内存计数，多实例要换 Redis。
- **多用户隔离**：练习记录、日报、复习队列、AI 讲解按 `user_id` 隔离。

## 3. 接口

| 方法 | 路径 | 鉴权 |
|------|------|------|
| POST | `/api/auth/register` | 否 |
| POST | `/api/auth/login` | 否 |
| GET | `/api/auth/me` | 是 |
| POST | `/api/questions`、`/api/questions/import`、`/api/knowledge-points` | ADMIN |
| 其余业务接口 | `/api/**` | 是 |

- `mvn test`：43/43 通过（新增 JWT、AuthService、CurrentUser、限流、Security MockMvc、管理员引导等 16 个 v3 测试）。
- 无 token 请求 `/api/knowledge-points` → 401。
- 本地 `.env` 配置的 learner 密码登录 → 200；`/api/auth/me` 返回 `id=1, username=learner, role=ADMIN`。

- 管理员引导：配置 ADMIN_USERNAME / ADMIN_PASSWORD 后重启，可创建或提升独立 ADMIN；关闭 demo 不影响该账号。

- Nginx：登录、带 token 的 API、SSE 均正常。

## 5. 配置

```bash
JWT_SECRET=至少32字节的随机串   # 无默认值；示例值会被拒绝
JWT_EXPIRE_HOURS=24
DEMO_USER_ENABLED=false
DEMO_USER_PASSWORD=             # 开启 demo 时必填，不能是 learner123
ADMIN_USERNAME=admin
ADMIN_PASSWORD=                 # 生产必填；ADMIN_REQUIRED=true 时缺失启动失败
ADMIN_REQUIRED=false
```

- 本地：默认无 demo；需要演示时在 `.env` 显式开启并设置密码；也可配独立管理员。
- 生产：必须换 `JWT_SECRET`，保持 demo 关闭，配置 `ADMIN_USERNAME / ADMIN_PASSWORD`，最好再上 HTTPS。

## 6. 边界与下一步

- 没有 refresh token、服务端登出黑名单、密码找回、邮箱/手机号验证。
- 有 ADMIN/USER 两级角色和题库写保护；还没有管理员后台、审核流、题目 owner。
- 没有 AI 配额、限流、支付；这些是产品化后续。
- JWT 放 localStorage，存在 XSS 风险；生产可改 HttpOnly Cookie + CSRF 方案。
- 多实例下无 session 依赖，但 AI 配额/限流需要 Redis 计数器。
- 题目详情已收口到 ADMIN，普通用户只能看练习提交后的记录；若未来题库页要展示解析，需要另开公开题面接口。
- 登录/注册限流目前是单实例内存；多实例部署要换 Redis 计数器。
