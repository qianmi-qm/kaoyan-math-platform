# v3：JWT 认证与多用户隔离

> 分支：`v3`；基线：`v2.0.3`（单用户 Redis + AI）
> 目标：把固定 `user_id=1` 换掉，让每个用户只看到自己的练习、报告、复习和 AI 讲解。

## 1. 做了什么

| 模块 | 实现 |
|------|------|
| 注册 | `POST /api/auth/register`，BCrypt 存密码，用户名唯一 |
| 登录 | `POST /api/auth/login`，返回 access 2h + refresh 7d |
| 当前用户 | `GET /api/auth/me` |
| 鉴权 | Spring Security 6 + `OncePerRequestFilter`；除登录/注册/刷新/Swagger 外全部要求 Bearer token |
| 角色 | `user.role`（USER/ADMIN）；题库/知识点写接口仅 ADMIN；管理员可管理用户角色、编辑题目 |
| 用户上下文 | `CurrentUser` 从 `SecurityContext` 取 `LoginUser`，删除 `app.default-user-id` |
| 数据隔离 | 所有业务查询继续使用 `user_id` 参数，只是来源从固定值改成登录用户 |
| 前端 | `/login`、`/account`、`/admin`；axios 自动带 token/刷新；多标签同步；非管理员隐藏题库导入 |
| 迁移 | `AuthSchemaMigration` 给旧 `user` 表补 `password_hash` / `role`；`DemoUserInitializer` 管理显式 demo 账号；`AdminUserInitializer` 独立创建/提升管理员 |

## 2. 关键设计

- **无状态 Session**：JWT 放 `Authorization: Bearer ...`，服务端不存 session，扩容不需要粘性会话。
- **密钥**：`JWT_SECRET` 无默认值，缺失/示例值/少于 32 字节直接启动失败；不再有可伪造的默认 secret。
- **密码**：BCrypt，不存明文；登录失败统一“用户名或密码错误”，不暴露用户是否存在。
- **401 结构**：Security 的 EntryPoint 也返回 `Result{code:4010,...}`，和业务异常一致。
- **SSE 异步**：`SseEmitter` 完成时会走 ASYNC dispatch，Security 放行 `DispatcherType.ASYNC/ERROR`；用户 id 在请求线程取出后传入 `ai-explain` 线程池，不依赖自动跨线程传播。
- **演示账号**：默认关闭；开启时必须显式设置非默认 `DEMO_USER_PASSWORD`，learner 会被提升为 ADMIN。关闭时清空 learner 的历史密码；已存在密码时不再覆盖，页面改密可保留。
- **管理员引导**：生产设置 `ADMIN_USERNAME / ADMIN_PASSWORD` 独立创建或提升 ADMIN；已存在的管理员密码不会被 env 覆盖，需要轮换时显式 `ADMIN_PASSWORD_FORCE=true`。`ADMIN_REQUIRED=true` 时缺失且无现有管理员会启动失败。
- **权限**：注册用户默认 USER；题库/知识点写接口和题目详情 `hasRole('ADMIN')`，普通用户只读；管理员可在 `/admin` 调整其他用户角色，不能改自己。
- **多标签**：token 刷新后通过 `storage` 事件同步；其他标签收到 401 时先同步最新 token 再重试，避免互相踢下线。
- **token 生命周期**：access 2h + refresh 7d；refresh 单次轮换，登出/改密递增 `user.token_version`，旧 access/refresh 立即失效。
- **限流**：登录按 `username+IP` 5 次/5 分钟 + IP 30 次/5 分钟；注册按 IP 10 次/小时；超限 429。优先 Redis 共享计数，Redis 不可用时降级本地内存。
- **多用户隔离**：练习记录、日报、复习队列、AI 讲解按 `user_id` 隔离。

## 4. 验收证据（2026-10-19）

- `mvn test`：63/63 通过（新增 JWT、AuthService、CurrentUser、限流、Security MockMvc、管理员引导、AI 配额、用户管理、题库编辑、多标签同步、邮件 token、拍照搜题/历史等 36 个 v3 测试）。
- 无 token 请求 `/api/knowledge-points` → 401。
- 本地 `.env` 配置的 learner 密码登录 → 200；`/api/auth/me` 返回 `id=1, username=learner, role=ADMIN`。
- 错密码 → 401；注册 `bob_test` → 200，返回 `role=USER`。
- 权限：bob 创建题目 403、导入 403、列表 200、题目详情 403；learner（ADMIN）可管理。
- 限流：同一账号+IP 连续 5 次错密码后第 6 次 429；同一 IP 30 次跨账号错误也会 429；成功登录清零账号级计数。
- 管理员引导：配置 ADMIN_USERNAME / ADMIN_PASSWORD 后重启，可创建或提升独立 ADMIN；关闭 demo 不影响该账号。
- 管理员改密：页面修改密码后重启仍生效；env 不会覆盖已有 hash，需要轮换用 `ADMIN_PASSWORD_FORCE=true`。
- AI 配额失败退款：模型连接失败时 request_count 退回，实测 used 保持 0。
- token：refresh 轮换成功；旧 access/旧 refresh 均 401；logout 后 access 401。
- 默认 secret 伪造 token → 401；关闭 `DEMO_USER_ENABLED` 后 learner 登录 401，重新开启可恢复。
- AI 配额：每用户每日 20 次真实模型调用；mock 一次后 used=1、token_estimate>0；无 key 降级不扣配额。
- 密码修改：旧 token 401、旧密码 401、新密码 200，验证 token_version 递增。
- 邮箱/找回：注册带 email 后日志输出验证链接；验证后 `emailVerified=true`；忘记密码日志输出 30 分钟重置链接，重置后旧密码 401、新密码 200。
- token 安全：数据库只存 SHA-256，明文只在邮件；reset/verify 都是单次消费。
- 拍照搜题：mock vision 返回题干/答案/步骤，used=1、token_estimate>0；图片不落盘；无 vision key 时 4001 提示。
- 搜题历史：真实 DeepSeek 调用后 `recordId` 落库；历史列表返回题干/答案/步骤/知识点；收藏筛选、删除、用户隔离均验证。
- 同类题：历史知识点能匹配题库，返回题目不含答案；`mode=QUESTION` 可一键创建单题练习。
- 上传限制：Nginx 10MB、后端 vision 8MB；只接受 JPG/PNG/WebP magic bytes。
- 多用户隔离：练习/日报/复习/AI 记录均按 user_id。
- AI：无 token 401；learner 对自己记录 SSE 正常；bob 访问 learner 的记录返回 `做题记录不存在`。
- 管理员用户列表：USER 403，ADMIN 200；管理员不能改自己的角色。
- 题库编辑：ADMIN 创建/编辑题目成功，题干/答案/知识点更新；USER 403。
- 多标签：其他标签通过 storage 同步新 token；刷新失败时先同步再重试，避免互踢。
- Nginx：登录、带 token 的 API、SSE 均正常。

## 5. 配置

```bash
JWT_SECRET=至少32字节的随机串   # 无默认值；示例值会被拒绝
JWT_EXPIRE_HOURS=2
JWT_REFRESH_DAYS=7
DEMO_USER_ENABLED=false
DEMO_USER_PASSWORD=             # 开启 demo 时必填，不能是 learner123
ADMIN_USERNAME=admin
ADMIN_PASSWORD=                 # 生产必填；ADMIN_REQUIRED=true 时缺失启动失败
ADMIN_REQUIRED=true
ADMIN_PASSWORD_FORCE=false      # 需要 env 覆盖管理员密码时设 true
AI_DAILY_QUOTA=20
MAIL_FROM=no-reply@kaoyan.local
APP_BASE_URL=http://localhost:5173
MAIL_LOG_LINKS=true             # 未配 SMTP 时日志输出链接；生产 false
MAIL_HOST=                      # SMTP host；为空则只打日志
MAIL_PORT=587
MAIL_USERNAME=
MAIL_PASSWORD=
AI_VISION_ENABLED=true
AI_VISION_BASE_URL=https://api.openai.com/v1
AI_VISION_API_KEY=              # 拍照搜题视觉模型 key；不填则页面提示未配置
AI_VISION_MODEL=gpt-4o-mini
AI_VISION_TIMEOUT_SECONDS=90
AI_VISION_MAX_IMAGE_MB=8
```

- 本地：默认无 demo；需要演示时在 `.env` 显式开启并设置密码；也可配独立管理员。
- 生产：必须换 `JWT_SECRET`，保持 demo 关闭，配置 `ADMIN_USERNAME / ADMIN_PASSWORD`，最好再上 HTTPS。

## 6. 边界与下一步

- 有拍照搜题 MVP + 搜题历史/收藏错题本 + 同类题练习；还没有题库拍照匹配、手写批改、多页试卷。
- 搜题历史只存识别文本，不存原图；用户可删除。
- 没有强制邮箱验证；验证状态只展示，不阻断登录。
- 有 ADMIN/USER 两级角色、用户角色管理、题目新增/编辑；还没有题目删除、审核流、题目 owner、账号禁用。
- 有 AI 每日配额/用量表；还没有支付、套餐、成本报表。
- JWT 仍放 localStorage，存在 XSS 风险；生产可改 HttpOnly Cookie + CSRF 方案。
- 题目内容已接 DOMPurify；KaTeX 仍保留。
- 题目详情已收口到 ADMIN，普通用户只能看练习提交后的记录。
- 限流已用 Redis 共享计数；Redis 故障时降级本地内存。
