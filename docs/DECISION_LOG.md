# 决策日志

> 每做一个设计选择就记一行。它同时是"想清楚"的工具和面试前的复习提纲。
> 已有条目是骨架阶段的架构决策——建议逐条挑战一遍：你能不能给出不同的理由？

| 日期 | 决策点 | 选择 | 备选方案 | 理由 |
|------|--------|------|----------|------|
| 2026-08-17 | ORM | MyBatis | Spring Data JPA | SQL 完全可控，索引/聚合/分页优化都发生在明面上，是本项目的主要学习素材 |
| 2026-08-17 | 复习触发 | 到期实时查询（无 @Scheduled 物化） | 凌晨物化当日清单 | v1 量小，实时查询走索引足够快；等量大了再演进（避免过度设计） |
| 2026-08-17 | 报告存储 | 生成时存 JSON 快照 | 查看时实时计算 | 复盘要看"当时的状态"；口径升级后历史不漂移 |
| 2026-08-17 | 做题计时 | 服务端计算 duration | 信任前端上报 | 前端数据不可信是安全常识；且自评场景仍需服务端时间线 |
| 2026-08-17 | 时间获取 | 全局注入 Clock Bean | 各处 LocalDate.now() | 单测可注入固定时钟，艾宾浩斯周期测试不需要改系统时间 |
| 2026-08-17 | 导入幂等 | content_hash 唯一键 | 无判重 | 重复导入 Excel 不产生脏数据，重复行进 duplicated 统计 |
| 2026-08-17 | 单用户 | 预留 user_id + 配置默认值 | 完整账号体系 | v1 不为假想需求写代码；字段留好，扩展成本低 |
| 2026-08-17 | 领域算法 | 纯静态类（无 Spring 依赖） | @Service 注入 | 掌握度/调度是纯函数，脱离容器可毫秒级测试，也强制了"领域与框架分离" |
| 2026-10-18 | 启动级联调 | 临时 MySQL 8（3307）+ 独立账号，不动本机 3306 | 改本机 root 密码 / 停本机服务 | 本机 3306 凭据未知，临时实例可随时丢弃，联调结果与真实部署等价 |
| 2026-10-18 | XML 注释规范 | mapper 注释分隔线用 `=`，禁用 `--` | 保留长横线 | XML 注释内容不允许出现 `--`；本次因此导致 MyBatis 启动解析失败（单测覆盖不到启动） |
| 2026-10-18 | 压测口径 | 本机单实例、固定并发/时长，记录 QPS 与 p95 | 不压测 / 只看平均延迟 | 有基线数字且能讲清环境局限，避免把本地数字当生产容量 |
| 2026-10-18 | MySQL 宿主端口 | compose 用 `${MYSQL_PORT:-3306}`，本机用 3307 | 固定 3306 / 去掉端口映射 | 开发机 3306 常已有 MySQL；可覆盖端口让 compose 在本地也能一键起 |
| 2026-10-18 | Docker 中文字符集 | schema 首部显式 `SET NAMES utf8mb4` | 依赖客户端默认字符集 | 容器初始化客户端字符集不确定，显式声明才能保证中文初始数据不乱码 |
| 2026-10-18 | Docker 构建代理 | compose build args 注入 HTTP(S)_PROXY / MAVEN_OPTS | 在 Dockerfile 里硬编码代理 | BuildKit 的 RUN 容器不继承宿主代理；Maven 还需 JVM -D 参数，build args 默认空值不污染镜像 |
| 2026-10-18 | 前端契约 | `api/normalize.js` 适配层 | 改 mock 或改后端 VO | mock 与真实 VO 字段不同；集中适配，页面不猜字段，并加 contract check |
| 2026-10-18 | 异常状态码 | `ResponseEntity` + 4xx/5xx | 全部 HTTP 200 + body code | HTTP 语义、监控、前端错误处理都更正确 |
| 2026-10-18 | 批量查询 | `selectByIds` / 窗口函数取最近 N 次 | 逐题查询 | 报告 4N+1 降到常数级，列表/练习/复习同步 |
| 2026-10-18 | 复习并发 | `active_key` 生成列 + 唯一索引 + upsert | select-then-insert | 并发答错只保留一条 active，避免重复复习 |
| 2026-10-18 | 幂等哈希 | SHA-256 替代 MD5 | 保留 MD5 | 判重场景抗碰撞更好，列宽 32→64 |
| 2026-10-18 | 日报口径 | 今天实时、历史快照、区间逐日补 0 | 首次查看即固化 | 当天新做题不会被旧快照挡住；趋势图不断点 |
| 2026-10-18 | v2 报告缓存 | Cache-Aside，`report:{userId}:{date}`，TTL 25h+抖动 | 注解缓存 / 不缓存 | 显式控制 key 与失效；练习提交先更 DB 再删缓存 |
| 2026-10-18 | v2 缓存降级 | 异常后 30 秒熔断，直接查库 | 每次等 Redis 超时 | 避免 Redis 故障把日报接口拖慢；页面不 500 |
| 2026-10-18 | v2 流式协议 | SSE | WebSocket | AI 讲解单向推送，HTTP 原生、断线重连简单 |
| 2026-10-18 | v2 AI 复用 | 成功后按 `(user_id, question_id, answer_hash)` 落库 | 每次重新生成 | 二次查看不耗 token；不同错答分别讲解，避免复用错误答案的讲解 |
| 2026-10-18 | v2.0.1 迁移 | 启动时 `V2SchemaMigration` 幂等补齐 | Flyway / 清库重建 | 旧库自动加 `answer_hash`、回填、换索引，不丢数据；后续规模大了再上 Flyway |
| 2026-10-18 | v2 AI 降级 | 无 key/超时/报错返回解析文本 | 直接 500 | 练习流程不能被外部模型阻塞；页面必须有内容 |
| 2026-10-18 | v2 单用户 | 继续固定 user_id，不做认证 | v2 一并上账号体系 | 先验证 AI/缓存技术链路；认证留到产品阶段，避免一次改动过大 |
| 2026-10-19 | v3 认证 | JWT + 无状态 Session | Session + Cookie / OAuth2 | SPA 直接带 Authorization，扩容不用粘性会话；refresh token 后续补 |
| 2026-10-19 | v3 用户隔离 | `CurrentUser` 从 SecurityContext 取 user_id | 业务层继续手传 userId | 改动集中在上下文，练习/报告/复习自动按用户隔离 |
| 2026-10-19 | v3 密码 | BCrypt | 明文/MD5 | 自带 salt、慢哈希；登录失败统一文案，避免枚举用户 |
| 2026-10-19 | v3 SSE 异步 | 放行 ASYNC/ERROR dispatch + 请求线程取 userId | 依赖 SecurityContext 跨线程 | `SseEmitter` 完成会二次 dispatch，JWT 不在异步线程；显式传 userId 更稳 |
| 2026-10-19 | v3 默认密钥 | `JWT_SECRET` 无默认值，缺失/示例值启动失败 | 保留 dev 默认值 | 默认 secret 等于公开认证后门；宁可启动失败 |
